# 意图识别失败兜底引导实施记录

**实施日期：** 2026-11-04  
**对应设计：** `意图识别失败兜底引导设计文档_V1.1.md`  
**实施范围：** 仅替换意图识别失败后的固定兜底提示；成功链路未改动。

---

## 1. 现状核对结论（与设计描述的差异）

| 设计假设 | 实际代码 | 结论 |
| --- | --- | --- |
| Tool Registry 未参与处理链路 | `ToolRegistry` 只被 `/agent/runs/{id}/details` 的展示字段和单测引用；LangGraph 执行链路不经过它 | 与设计一致 |
| 意图识别先由 LLM 判定 | `build_agent_graph` 的 `classify` 节点调用 `llm.classify_intent()`，路由集合固定为 8 种 | 一致 |
| 意图识别后由 Python 解析文本并拼装 Task | `prepare` 节点调用 `AgentBusinessService.prepare_task_*` / `prepare_vocabulary_*`，内部用正则解析词库名、序号、听写配置 | 一致 |
| 失败后返回固定提示 | 原实现只有 `respond` 节点末尾一句固定文案，覆盖 `chat` 与 `unclear` | 一致，已替换 |

补充事实：

- `MockLLMAdapter` 无法识别时统一返回 `chat`，`unclear` 实际很少出现；两者都走同一兜底分支。
- `main_agent.txt` 目前只用于生成 `prompt_version`，`classify_intent` 使用的是代码内固定英文提示词，本次未改动。

## 2. 意图识别失败分支位置

`backend/app/modules/agent/runtime.py` 的 `build_agent_graph`：

```text
classify → route_after_classify
             ├── task_*/vocabulary_* → prepare → wait/execute（原有流程，未改动）
             └── learning             → respond（原有学习统计，未改动）
             └── chat / unclear       → respond → FallbackGuidanceService
```

被替换的固定提示：`"我可以帮你创建和管理学习任务、导入词库或查看学习记录。请直接描述你的目标。"`

`prepare` 节点内的防御性默认分支（`"暂时无法明确识别这个操作，请补充目标。"`）在当前路由下不可达，且不属于意图识别失败，保留未动。

## 4. 首次能力盘点结果

只收录能从对话页入口走到真实 Service 与持久化的能力：

1. 创建听写任务（`task_create` → `prepare_task_*` → `TaskService.create`）。
2. 修改听写任务（`task_update` → `TaskService.update`）。
3. 删除听写任务（`task_delete`，两阶段确认，级联删除练习记录）。
4. 创建个人词库（`vocabulary_create`，创建为空词库）。
5. 导入词库（`vocabulary_import`，需先上传 `.xlsx`/`.csv`）。
6. 查看学习统计（`learning` → `LearningService.stats`）。

写入「明确不支持」：教材/课本自动生成听写任务、修改答题结果、公共词库发布管理、跨用户管理、语音/图片/文件管理。

未收录：Tool Registry 中的 `learning.stats` 等定义（未接入执行链路）、后台管理员能力（普通用户对话入口不可达）、仅存在于设计稿的能力。

## 5. 兜底 Prompt 组装方式

```text
PromptRegistry.get("fallback_guidance")            # 行为规则（可版本化、可算哈希）
  .render({"capability_guide": guide.content})     # 注入 Guide 全文
  + 用户原始输入作为 user message
  → llm.generate_guidance(system, user_input)
```

- Guide 通过 `get_document("capability_guide")` 读取，计算 SHA-256，取前 12 位写入日志。
- 每次兜底重新读取文件，Guide 更新后无需重启。
- 用户输入不拼进 system，避免被当成指令注入规则区。

## 6. 失败降级

| 场景 | 行为 | 日志 |
| --- | --- | --- |
| Guide 缺失/不可读 | 返回通用提示，不猜测能力 | `capability guide unavailable code=...` |
| 兜底 Prompt 缺失 | 同上 | `fallback prompt unavailable code=...` |
| LLM 超时/限流/5xx/解析失败 | 同上，run 正常 `completed` | `fallback guidance llm failed code=...` |
| LLM 返回空文本 | 同上 | `fallback guidance empty response` |
| 正常生成 | 返回 LLM 文本 | `agent fallback guidance route=... source=... guide=...` |

通用提示为：

> 抱歉，我暂时没能理解你的需求。可以换一种说法，描述你想完成的学习任务、词库或学习记录吗？

## 7. 如何确认兜底不进入业务解析与执行

1. `respond` 节点只调用 `learning_stats_text()`（learning 路由）或 `guidance.respond()`；不调用任何 `prepare_*`。
2. 兜底结果没有 `pending_action`，`_execute_new_run` 只写 `message` + `done` 事件，不产生 `confirmation_required`。
3. 测试断言：兜底前后 `/api/v1/tasks` 数量不变；事件中无 `confirmation_required`。
4. 用户再次输入会创建新 run，重新走 `classify`，测试覆盖。

## 8. 测试结果

```text
cd backend
.venv/bin/pytest -q
86 passed
```

新增覆盖：

- Guide 为真实内容、无模板占位符；
- Prompt 注入 Guide 全文、用户输入单独传入；
- Guide 缺失、LLM 失败时降级为通用提示；
- 两类无法识别输入返回不同且包含原输入关键词的引导；
- 兜底不写业务数据、不产生确认事件；
- 教材能力被明确拒绝；
- 替换 LLM 后确认收到真实 Guide 与原始输入；
- 兜底 LLM 失败后 run 仍 `completed`，用户可继续；
- OpenAI 兼容适配器以纯文本模式调用（无 `response_format`）。

## 9. 发布注意

- 新增两个 Prompt 文件必须随 release 一起上传（`backend/app/modules/agent/prompts/`）。
- 无数据库迁移、无前端构建产物变化。
- 生产 `FLA_LLM_PROVIDER=openai_compatible`，兜底会真实调用 DeepSeek，需关注 429/超时日志与 token 成本。
- 兜底调用失败不影响 run 状态，但用户会看到通用提示，需通过日志定位。
