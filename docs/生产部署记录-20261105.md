## 3. 多轮上下文与候选词库收敛

**上线时间：** 2026-11-05 18:12 CST
**代码提交：** `c9fde50 feat: carry conversation history and cap task library candidates`
**Release：** `/opt/project2/releases/familylearning-c9fde50`
**回滚目标：** `/opt/project2/releases/familylearning-70439e1`
**数据库：** 无迁移
**前端：** 无改动（仍为 `assets/index-eS8JnMA3.js`）

### 背景

1. `task_create` 的 System Prompt 注入了当前用户可见的全部词库（生产约 150 个），Prompt 过长且模型容易选错。
2. 意图识别与工具流程只带当前这一句用户输入，用户在追问后只回复「词库名」或「第一个」时会被识别成 `chat`，对话断裂。

### 实现

- `AgentRuntime._recent_history`：取当前会话最近 6 条自然语言消息（排除当前 run 和工具消息），每条截断 500 字。
- `classify_intent(text, history)`：分类请求改为 `system + history + 当前输入`；System Prompt 增加「用户可能在回答上一轮追问」的规则。
- `TaskCreateToolWorkflow`：工具调用 messages 同样带 history，模型能看到上一轮的「创建任务」和助手追问。
- 词库候选收敛：每学科最多 3 个，按「被点名 → 个人库 → 最近更新」排序；即使被点名的词库不在默认前 3，也会强制纳入。
- 候选 Prompt 明确标注「不是全部」及该学科词库总数；追问时要求列出候选名称，便于下一轮用「第一个」回答。
- Mock 分类器同步支持追问场景，避免本地开发时行为差异。

## 4. 语文听写页不再显示词语本身

### 背景

语文听写时，页面上直接出现了要默写的词语。

### 根因

语文词库在导入时，`meanings` 填的就是词语本身（线上「五年级上册 第四单元」里 `毁灭 → ["毁灭"]`）。听写页的提示卡有「语文拼音」「中文含义」两栏，后者印的正是要写的字，等于把答案摆在卷面上；拼音反而是唯一有效提示。

### 实现

- `DictationPracticePage` 新增 `isChineseDictation` 与 `meaningTextOf()`：语文学科下，只要任一含义包含词条 `word` 就返回空串，该栏不渲染；真写了释义的词库（如「荡漾 → 水波轻轻起伏的样子」）照常显示。

- 提示卡标题在语文下改为「词语发音（直接读出）」，与任务创建页的下拉选项一致；播放区说明按学科分支（语文：只显示拼音，不显示词语本身）。
- 反馈卡的正确答案仍显示「词语 + 拼音」，只是不再重复那一行「中文含义」。

## 4. 修复上一轮“打开任务”链接泄漏到新消息

**上线时间：** 2026-11-05 18:17 CST
**代码提交：** `ebcc59a fix: reset task links when starting a new agent run`
**Release：** `/opt/project2/releases/familylearning-ebcc59a`
**回滚目标：** `/opt/project2/releases/familylearning-c9fde50`
**前端：** 无改动（仍为 `assets/index-eS8JnMA3.js`）
**数据库：** 无迁移

### 现象

用户在对话里完成过一次任务创建后，后续助手消息（例如创建任务前的追问）仍带着「打开任务」链接，看起来像任务已经创建成功。

### 根因

`links` 存在 LangGraph checkpoint 的会话状态里。`_execute_new_run` 启动新一轮时重置了 `pending_action`、`draft_version`、`tool_trace`，但没有重置 `links`；确认执行后写入的「打开任务」链接会被下一轮的 `respond` / tool workflow 原样继承，最后写进新消息。

### 修复

- 每轮新 run 的初始状态显式写入 `links=None`。
- 取消、确认失效、配置版本/哈希不匹配、删除任务第一次确认等非执行分支也清空 `links`。
- 只有真正执行成功后才写入 `result.links`。
