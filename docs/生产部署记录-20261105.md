## 3. 多轮上下文与候选词库收敛

**上线时间：** 2026-11-05 18:12 CST
**代码提交：** `c9fde50 feat: carry conversation history and cap task library candidates`
**Release：** `/opt/project2/releases/familylearning-c9fde50`
**回滚目标：** `/opt/project2/releases/familylearning-70439e1`
**数据库：** 无迁移
**前端：** 无改动（仍为 `assets/index-eS8JnMA3.js`）

### 背景

1. `task_create` 的 System Prompt 注入了当前用户可见的全部词库（生产约 150 个），Prompt 过长且模型容易选错。
2. 意图识别与工具流程只带当前这一句用户输入，用户在追问后只回复「词库名」或「第一个」时会被识别成 `chat`，对话断裂。

### 实现

- `AgentRuntime._recent_history`：取当前会话最近 6 条自然语言消息（排除当前 run 和工具消息），每条截断 500 字。
- `classify_intent(text, history)`：分类请求改为 `system + history + 当前输入`；System Prompt 增加「用户可能在回答上一轮追问」的规则。
- `TaskCreateToolWorkflow`：工具调用 messages 同样带 history，模型能看到上一轮的「创建任务」和助手追问。
- 词库候选收敛：每学科最多 3 个，按「被点名 → 个人库 → 最近更新」排序；即使被点名的词库不在默认前 3，也会强制纳入。
- 候选 Prompt 明确标注「不是全部」及该学科词库总数；追问时要求列出候选名称，便于下一轮用「第一个」回答。
- Mock 分类器同步支持追问场景，避免本地开发时行为差异。
