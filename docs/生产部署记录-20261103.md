## 4. 顺带修复的生产缺陷

`/api/v1/agent/runs/active` 每次请求都返回 500，日志为：

```
(1038, 'Out of sort memory, consider increasing server sort buffer size')
SELECT ... FROM agent_runs WHERE user_id=... AND status IN (...) ORDER BY created_at DESC
```

原因：`agent_runs` 里有一条 `waiting_confirmation` 记录，`pending_action_json` 长 **319431 字符（约 312KB）**，而 MySQL 的 `sort_buffer_size` 是 256KB；对含大 JSON 的行做排序时整行要进排序缓冲，直接溢出。该错误在旧 release（`familylearning-198c125`）时期就已出现，10-28 起反复发生，不是本次发布引入。

修复：活跃运行查询与事件列表都改为「先只按主键排序取 id，再回表加载」，避免大字段参与排序（`backend/app/modules/agent/repository.py`），并新增 `backend/tests/test_agent_active_run.py` 覆盖 400KB 级待确认动作。

修复后该接口返回 200，能正常带出那条挂起的确认草稿（一个基于 7956 词词库创建任务的草稿，草稿本身未确认、未落库）。

## 7. 补充发布（10:34）：修复「答对后才能进入下一组」

**上线提交：** `a0eb8c4`  
**当前 release：** `/opt/project2/releases/familylearning-a0eb8c4`  
**回滚目标：** `familylearning-ae386ad`（09:26 版）

### 问题

任务里的「答对后才能进入下一组」只做了保存和展示，练习流程完全没有读取这个配置。所以一组的词不管答对答错都会线性走到下一个词，用户看到的现象就是"错了几个之后自动进入下一组"。

### 修复

- `submit_answer` 读取任务 `config_json.repeat_until_correct`：开启后，同一个词必须连续拼对 2 次才推进 `current_index`，答错或只对一次都留在本词继续练；连续次数从本次作答记录倒着数，错一次即清零。
- 答案序号从"第几个词"改为"第几次作答"，满足 `(attempt_id, sequence_no)` 唯一约束；`score` 改为按词去重，避免出现 3/2。
- 练习页：答对但未过关时不自动跳题，显示「本词连续拼对 1/2 次」并提供「再拼一次」按钮；过关后仍 1 秒自动继续。
- 强制答对模式下自动播放不再到点换词（否则等于没答对也能过），只保留进词发音与手动重播。
- 任务创建/详情的开关文案补全为「每个词连续拼对 2 次才进入下一个词」。
- 错题复习保持原有设计（一次过一遍、两轮复习移出错题池），不套用连对规则。

### 验收

- 生产真机冒烟（临时任务，验完已删除）：答错 → `currentIndex` 仍 0；第 1 次拼对 → 仍 0；第 2 次连对 → 1。
- 线上 `admin` 的「雅思1」任务（`repeatUntilCorrect=true`、875 组）即刻生效，无需重建。
- 前端产物 hash 与本地构建一致（`index-Ce0z9jKA.js`、`DictationPracticePage-C8iTNgVB.js`），页面无控制台错误。
- 后端 74 passed（新增 `test_repeat_until_correct.py` 3 条）；E2E 30 passed（新增 `repeat-until-correct.spec.ts`）。

## 8. 补充发布（11:02）：强制重做改成轮次制

**上线提交：** `33e0ade`  
**当前 release：** `/opt/project2/releases/familylearning-33e0ade`  
**回滚目标：** `familylearning-a0eb8c4`（10:34 版）  
**数据库：** 新增迁移 `0006_practice_attempt_round`（`practice_attempts.round_no`，默认 1）

### 规则调整

10:34 那版把「答对后才能进入下一组」实现成了「答错就卡在本词，必须原地连对两次」，和实际想要的练习节奏不一致。现在改成按轮推进：

- 组内每个词每轮只拼一次，**答错也照常进入下一题**。
- 一轮走完后，只把这一组里拼错过、且还没连续拼对两次的词拿出来重练（没错过的词不再出现）。
- 错词连续两轮拼对即过关；本组所有词都过关才进入下一组，进入下一组时轮次重置为 1。
- 错题复习（`kind=wrong`）保持原设计：一次过一遍，连续两次复习都对就移出错题池。

### 实现要点

- `practice_attempts.round_no` 记录当前轮次；本轮待练词复用 `target_entry_ids` 保存，`current_index` 指向本轮队列位置。
- `_close_round`：一轮结束按「是否拼错过 + 末尾连续正确次数」筛出下一轮的词；全过关则取下一组，最后一组则完成。
- 进度改为按「已过关词数 / 总词数」计算：没错过的词答对一次就过，错词要连对两次。
- 旧版本创建、还没轮次队列的进行中练习，恢复时按 `current_index` 所在分组自动补齐队列（`_ensure_round_queue`）。
- 前端练习页：分组条新增「练习轮次」，第二列在强制重做时变成「本轮进度」；轮次/分组切换时先展示本题反馈，点「下一题」再切到下一轮并给出提示；移除「再拼一次」。

### 验收

- 生产真机冒烟（临时任务，3 词，验完已删 204）：第一轮 3 词全走一遍 → 第 2 词答错 → 轮次结束后队列只剩 1 词（round 2）→ 拼对一次 round 3 → 再拼对完成（3/3）。
- 前端产物 hash 与本地一致（`index-DOv8cp0E.js`、`DictationPracticePage-Dv460c2r.js`），任务页/详情页无控制台与接口错误。
- 后端 75 passed；E2E 32 passed；`npm run build` 通过。
