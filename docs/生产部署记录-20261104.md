## 1. 手机软键盘弹起时练习页让位

**上线提交：** `c328d89`  
**当前 release：** `/opt/project2/releases/familylearning-c328d89`  
**回滚目标：** `familylearning-33e0ade`（11-03 11:02 版）  
**数据库：** 无迁移（纯前端改动）

### 问题

手机浏览器里点开听写输入框后，输入法会占掉屏幕下方近一半高度，而练习页仍按 `100vh` 排版：页面底部被键盘盖住，`提交拼写` / `下一题` 按钮点不到，答题时得先收起键盘再操作。

「线上听写」和「错题复习」是同一个组件（`/practice/dictation/:taskId` 与 `.../wrong` 都渲染 `DictationPracticePage`），外壳由 `PracticeLayout` 提供，所以改在布局层一次覆盖两个页面。

### 实现

- 新增 `frontend/src/features/practice/useKeyboardViewport.ts`：监听 `window.visualViewport` 的 `resize` / `scroll`，用「见过的最高的视觉视口」当基准，`基准 - 当前高度 > 120px` 判定键盘弹起；横竖屏用「宽度变化 > 5px」重置基准。iOS 只缩视觉视口、安卓会缩布局视口，两种行为都能覆盖。
- `PracticeLayout` 在键盘态给外壳加 `.is-keyboard`，并写入 `--practice-vh`（视觉视口高度）与 `--practice-vt`（`offsetTop`，iOS 键盘弹起会把页面往上推）。外壳改 `position: fixed`，高度取可视区高度，`practice-main` 成为唯一滚动容器。
- 紧凑化：隐掉长说明文字（保留状态徽标）、底部原型说明、输入框 label、「按 Enter 也可以提交」、自动播放倒计时、音频区说明、朗读内容标签；播放键 64→38px，输入框 28→22px（≥16px 防止 iOS 自动放大），分组条改为单行 flex。
- 按钮固定：`.practice-card-footer` 改 `position: sticky; bottom: 0`，内容再长也钉在键盘上沿。
- 出反馈后播放区、提示卡、输入框都是重复信息，用 `:has(.answer-feedback)` 隐掉，只留「正确答案 + 你的答案 + 朗读 + 下一题」，小屏也放得下。
- 移动端全局提示条由底部改到顶部（`top: calc(var(--mobile-topbar-height) + 8px)`），否则正好压住提交按钮。
- `index.html` viewport 增加 `interactive-widget=resizes-content`（Chrome Android 直接缩布局视口）与 `viewport-fit=cover`（`env(safe-area-inset-bottom)` 生效前提）。

### 验收

- 本地：新增 `e2e/keyboard-viewport.spec.ts`（用 `setViewportSize` 压缩视口模拟键盘，只跑 mobile 项目），全量 E2E 34 passed / 2 skipped，`tsc` 与 `npm run build` 通过。

- 产物 hash 与本地构建一致（`index-lkgKfqp0.js`、`index-DtE2mYsw.css`、`DictationPracticePage-D2n_ujd1.js`）。

## 2. 答错后不再出现下拉条（手机练习页改一屏）

**上线时间：** 2026-11-04 17:0x（Asia/Shanghai）
**代码提交：** `9e3d83b fix: keep the mobile practice page on one screen`
**Release：** `/opt/project2/releases/familylearning-9e3d83b`
**回滚目标：** `/opt/project2/releases/familylearning-c328d89`
**数据库：** 无迁移（纯前端）

### 背景

线上反馈：单词拼错、错误提示出现后页面出现下拉条，需要先往下拉才点得到「下一题」。

### 根因

不是键盘布局的问题。用 iPhone 13 视口（390×664）实测：进入练习时整页 761px、答错后 1063px，比视口多出 **399px**。手机端练习页仍是「长文档 + 整页滚动」结构，反馈一出现（例句、重练提示、「你的答案」行）就把页面撑长，按钮被推到屏幕外。

### 实现

- `@media (max-width: 768px)` 把练习页改成 app 式一屏：`.practice-shell { height: 100dvh; overflow: hidden }`，`.practice-main` 成为唯一滚动容器，`.practice-card-footer` 改 `position: sticky; bottom: 0` 钉在底部。页面级 `documentElement.scrollHeight` 恒等于视口高度。
- 「答错后隐藏播放区 / 提示卡 / 输入框」原先只写在 `.is-keyboard` 下，现在扩大到该媒体查询（`.dictation-practice-card:has(.answer-feedback)`）。反馈态只剩「正确答案 + 你的答案 + 朗读 + 下一题」，一屏放得下；`practice-secondary-note`（原型说明）在手机上也隐藏。
- 滚动条彻底不显示：`.practice-shell` / `.practice-main` / `.offline-review-list` 加 `scrollbar-width: none` 与 `::-webkit-scrollbar { display: none }`；`html.keyboard-open` 时锁住 `html`/`body` 的 `overflow`。
- 新增 `.is-tight` 第二档压缩：`PracticeLayout` 用 `ResizeObserver` + `MutationObserver` 单向判定 `scrollHeight > clientHeight`，一旦放不下就收紧分组条（只留数字）、卡片与页脚，应对 300px 左右的极矮可视区。单向是为了避免压缩后不再溢出又弹回来抖动。
- `PracticeLayout` 在 `current`（当前题号）变化时把 `practice-main.scrollTop` 归零，否则上一题滚到一半的位置会带到下一题。
- 没有例句的词不再渲染空的 `blockquote`（此前会显示一条带光标的空白条），`DictationPracticePage` 与 `VocabularyPracticePage` 都改为 `entry.example || entry.exampleTranslation` 才渲染。

### 验收

- 本地 390×664：答题态与反馈态 `docScroll`、`main` 溢出均为 0，`下一题` 在视口内；390×380 / 390×300 键盘态仍是紧凑布局、零溢出。
- 新增 `e2e/keyboard-viewport.spec.ts` 用例「手机竖屏：答错提示出现后整页不出现下拉条」（断言整页与内部溢出 ≤1px、按钮 `toBeInViewport`）；`dictation-speech-modes.spec.ts` 里两条断言从 `.dictation-hint-card` 改到 `.answer-feedback`（提示卡此时已隐藏，音标在反馈卡里）。
- 全量 E2E **36 passed / 4 skipped**，`tsc`、`npm run build` 通过。
- 生产冒烟（`https://yidongxun.com`，临时用户 + 2 词词库 + 任务）：390×664 答题态/反馈态 `doc` 与 `main` 溢出均为 0；390×380 切到 `is-keyboard` 后同样为 0，`下一题` 底边在 380 以内；截图核对无滚动条、无裁切。
- 产物 hash：`index-DIvZzDCC.js`、`index-DNlCIja2.css`、`DictationPracticePage-CpkpdVzs.js`（与本地一致）。
