# 家庭学习助手技术决策记录

**版本：** 1.0  
**更新时间：** 2026-11-02

---

## TD-01 API 与前端数据边界

**决策：** 页面只依赖统一 `api` composition root。生产构建默认使用 HTTP Adapter；Mock Adapter 仅用于隔离的开发/测试。

**原因：** 保持 Phase 0 已建立的边界，避免页面直接依赖 LocalStorage 或 DTO 细节。

---

## TD-02 JWT 与 Refresh Session

**决策：** 短期 JWT Access Token + 数据库可撤销 Refresh Session。Refresh Token 轮换后旧会话立即撤销。

**原因：** 支持登出、停用账户和令牌撤销，同时避免每次请求查询会话表。

---

## TD-03 SSE 事件持久化

**决策：** Agent 事件写入 `agent_run_events`，使用 `(run_id, sequence)` 唯一约束；客户端通过 `after_sequence` 重放。

**验证：** 已通过事件顺序、游标重放和断点恢复测试。

---

## TD-04 LangGraph Checkpointer

**决策：** SQLite 用于本地开发；生产使用 `langgraph-checkpoint-mysql`。

**MySQL PoC 结果（2026-11-02）：**

- 实际数据库：MySQL Community Server 8.4.7，macOS arm64。
- 使用包：`langgraph-checkpoint-mysql 3.0.0`、`PyMySQL 1.2.3`。
- `PyMySQLSaver.from_conn_string()` + `setup()` 可正常建表。
- `interrupt` 状态可跨连接恢复。
- 完整 Agent 待确认任务可在应用进程重启后继续并完成写入。
- 重复创建 Checkpoint 表无异常。

**限制与要求：**

1. MySQL/MariaDB 版本必须满足依赖包最低要求（MySQL ≥ 8.0.19，MariaDB ≥ 10.7.1）。
2. MySQL 8 的 `checkpoint` 数据库默认排序规则必须为 `utf8mb4_0900_*`。若使用 `utf8mb4_unicode_ci`，Saver 内部 `JSON_TABLE` 生成的 `utf8mb4_0900_ai_ci` 字符串会与业务表字段发生排序规则冲突。
3. 推荐 Checkpoint 使用独立数据库，并在建库时显式指定 `COLLATE utf8mb4_0900_ai_ci`。
4. SQLite 仅用于开发测试，不作为生产恢复方案。

**生产建库示例：**

```sql
CREATE DATABASE familylearning CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE DATABASE familylearning_checkpoints CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

## TD-05 确认协议幂等

**决策：** `action_id` 使用 Agent Run ID；每次编辑递增 `draft_version` 并重新计算 `config_hash`。确认必须携带最新二元组。Run 状态机阻止重复确认产生第二次副作用。

---

## TD-06 两阶段删除

**决策：** 删除任务第一次确认只生成第二次确认动作并递增版本；第二次确认才调用 Task Service 删除。两阶段均不直接访问 Repository。

---

## TD-07 执行详情与脱敏

**决策：** 用户只能查看自己的执行详情；管理员可查看所有用户详情。返回前递归屏蔽 key 中包含 token、password、cookie、secret、credential 的字段，并替换 Bearer/sk- 凭证文本。

---

## TD-08 Tool 权限

**决策：** Tool Registry 在模型调用前按角色过滤；写入类流程只生成确认草稿，确认后才通过业务 Service 执行。Tool 不直接访问数据库。


## TD-09 SSE 执行与连接解耦

**决策：** Agent Graph 在后台线程执行，SSE 端点只轮询 `agent_run_events` 并发送事件。客户端断开不会取消 Graph；重连使用 `after_sequence` 补发。

**原因：** 解决断网、页面刷新和代理超时导致的运行中断/重复副作用风险。

---

## TD-10 前端认证与刷新

**决策：** Access/Refresh Token 由统一 HTTP Client 管理；401 时使用单例 Refresh Promise 轮换令牌并只重试一次原请求。生产默认使用 HTTP API，Mock 仅在 `VITE_API_MODE=mock` 时启用。

---

## TD-11 安全与可观测性

**决策：**

- Access Token 增加 `jti`，避免同一秒内令牌字节完全相同。
- 响应增加 `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy` 和 `Permissions-Policy`。
- `/api/v1/health/metrics` 提供请求数、错误数、状态分类和延迟。
- 上传限制扩展名和字节数，文件名哈希化，避免路径穿越。
- 管理员执行详情递归脱敏。

---

## TD-12 生产管理员 Bootstrap

**决策：** `seed_demo_data=false` 时可通过两组 `FLA_BOOTSTRAP_ADMIN_*` 环境变量创建两个初始管理员。仅当昵称不存在时创建，不覆盖已有密码。

## TD-13 Excel 列名兼容与模型映射

**决策：** 导入解析采用规则优先、模型兜底。

1. 先用扩展中英文同义词精确匹配标准字段，不调用模型。
2. 无法识别必需列时，将原始表头和最多 5 行样例（单元格截断到 200 字符）发送给 LLM。
3. Prompt 使用 `backend/app/modules/agent/prompts/header_mapping.txt`，返回 0 基列索引。
4. 服务端再次校验索引范围、字段重复、`word`/`meaning` 必填和模型输出类型；不信任模型直接写入。
5. 映射来源、置信度、原因、Token 使用量和 Prompt 版本保存到 `content_extractions.mapping_json`，前端展示“规则识别/模型识别”。
6. 模型不可用或映射无效时返回明确错误，不创建词库。

---

## TD-14 导入字段自动补充

**决策：** 解析完成后、用户确认前执行字段补全。

- 英文词条缺失音标或中文释义时调用 LLM。
- 含汉字的词条缺失拼音时调用 LLM；中文词语缺失释义时使用词条本身作为初始释义，避免无意义空白。
- 仅填补空字段，绝不覆盖上传文件或用户已输入内容。
- 每批数据只包含词条、缺失字段和已有字段；真实 Provider 使用文件化 Prompt。
- Mock Provider 提供演示词表与常用拼音映射；未知内容会进入预览错误提示，不会伪造结果。
- 模型不可用时导入不崩溃，仍生成可编辑预览并提示手动补充。
- 补充来源、完成数量、Token 使用量和 Prompt 版本写入 `content_extractions.mapping_json.enrichment`。

## TD-15 最新原型交互裁决

- 词条删除使用当前可见选择快照，并在筛选变化时清空选择，避免隐藏的旧选择被一并删除。
- Agent 解析“前 N 个单词”，默认任务模式为固定任务；界面不显示字面量 `all`，全选显示为 `1-N`。
- 固定任务仍锁定词条快照，但允许编辑名称、重做规则和听写配置。
- 任务创建/详情根据词库自动带出学科；V1 学习类型只读。
- Agent 创建任务或词库后返回稳定站内链接。
- 未产生任何 Attempt 的任务显示“开始学习”，已有 Attempt 才显示“继续学习”。
- 管理员可将自己创建的个人词库设为公共词库；公开后 owner 置空并立即发布。
- 英语和语文使用不同的 Excel 模板字段。
- 听写配置语义为“朗读内容”；练习页同时展示音标/拼音与中文含义，语音合成按配置朗读对应内容。

### 补充裁决（词库学科与选择状态）

- 上传解析必须显式携带页面当前学科，服务端不得将语文草稿硬编码为英语。
- 新建任务默认固定模式，切换词库后默认不选任何词条；只有用户全选或明确输入范围时才选择词条。
- Agent 导入预览必须为每个临时词条生成稳定唯一 ID，删除只过滤对应 ID。

### 补充裁决（分组进度与中文发音）

- 听写页面必须显示“第 X/Y 组、组内第 M/N 个”，固定任务显示第 1/1 组。
- 语文听写语音直接朗读汉字词语本身，不朗读拼音串；拼音和中文含义仅在页面作为提示同时展示。
- 英语听写仍按配置朗读英语单词或中文含义。

### 补充裁决（初始化管理员）

- 开发 seed 仅创建两个管理员：`admin / admin213`、`admin1 / admin222`。
- 登录页不再提供“或使用预置账户”的快捷入口；管理员必须手动输入账号密码。
- 生产环境仍通过 `FLA_BOOTSTRAP_ADMIN_*` 注入，不在迁移中写入固定生产密码。
