## 2. 产品定位与用户角色

### 2.1 产品定位

家庭学习助手以 AI Agent 作为统一入口，把学习资料解析、词库整理、听写任务创建、练习和学习记录串起来。用户不需要先理解系统菜单和固定流程，可以直接描述目标，由 Agent 生成待确认操作。

### 2.2 用户角色

| 角色 | 能力 |
| --- | --- |
| 普通用户 | 管理自己的词库和任务、导入内容、练习、查看自己的学习记录 |
| 管理员 | 管理公共词库、查看全部用户和只读学习概况、重置用户密码；不能代替用户修改答题结果 |

生产初始化管理员昵称为 `admin`、`admin1`。密码不写入本文，需从生产环境文件或密码管理系统获取。

## 3. 技术架构

### 3.1 技术栈

| 层 | 技术 |
| --- | --- |
| 前端 | React 19、TypeScript 5.9、Vite 8、React Router 7 |
| 后端 | Python 3.12、FastAPI、SQLAlchemy 2、Pydantic 2 |
| Agent | LangGraph 1.2、DeepSeek OpenAI-compatible API、SSE |
| 生产数据库 | MySQL 8.0.46，库名 `english_forest` |
| Checkpoint | `langgraph-checkpoint-mysql`，当前与业务库共用 MySQL 实例和库 |
| 文件存储 | 本地目录 `/opt/project2/shared/familylearning_uploads` |
| 生产进程 | systemd 托管，后端 8002，前端静态 SPA 8003 |

### 3.2 生产拓扑

```text
Internet
  -> Nginx :443
     -> /api/*  -> 127.0.0.1:8002  FastAPI / LangGraph
     -> /*      -> 127.0.0.1:8003  React SPA static server
  -> MySQL 127.0.0.1:3306 / english_forest
```

Nginx 配置：`/etc/nginx/conf.d/project2.conf`。API 请求最大 20 MB，代理读写超时 300 秒，以支持 Agent SSE。

### 3.3 关键设计

- 前后端完全分离；生产前端使用同源 `/api/v1`。
- 任务创建时保存词条快照，后续词库变化不影响已有任务。
- 重要 Agent 操作先产生待确认草稿，用户确认后才执行业务写入。
- Agent 执行事件持久化，SSE 断开后仍可继续，重连后按序号补发。
- 当前按单 worker 运行。多实例前需要独立 Agent Worker、共享队列和执行租约设计。

## 5. 已实现的核心业务

### 5.1 认证与账户

- Access Token 默认 30 分钟，Refresh Token 默认 30 天。
- Refresh Session 可撤销并轮换。
- 生产 CORS 仅允许 `https://yidongxun.com` 和 `https://www.yidongxun.com`。
- 管理员可停用用户、重置密码和查看只读学习统计。

### 5.2 词库与导入

- 个人词库、公共词库、发布/撤回、复制为个人副本。
- 支持 `.xlsx` 和 `.csv` 上传、模板下载、服务端解析、预览编辑、确认导入。
- 表头优先使用规则识别，无法识别时通过 LLM 生成字段映射。
- 英文可补音标和中文释义，中文词语可补拼音。
- 解析和字段补全先预览，用户确认后落库。

### 5.3 任务

- 固定任务和长期任务。
- 创建时保存词条快照，固定任务内容不可修改；长期任务使用稳定快照参与练习。
- 任务支持修改名称、分组和听写配置，支持两阶段确认删除。
- 任务列表使用摘要接口，详情按需加载完整快照。

### 5.4 听写与练习

- 线上听写由服务端自动判分；线下听写由用户自查错误项。
- 支持手动/自动播放、朗读次数、提示内容、开启/关闭朗读。
- “强制重做”按轮次执行：一轮内每个词走一遍，错词下一轮继续，连续两轮拼对后过关。
- 错题复习为独立 Attempt，连续两次复习正确后移出错题池。
- 练习中断后可恢复；任务进度和学习统计由答题事实重算。
- 听写提交已做增量优化，不再每题加载整个任务快照。

### 5.5 Agent

- 支持自然语言创建/修改/删除任务、创建/导入词库、查询学习记录。
- 意图无法识别时读取 `capability_guide.md`，由 LLM 生成与用户输入相关的引导文本；该分支不执行任何业务操作。
- 重要写入必须经过 `action_id + draft_version + config_hash` 确认协议。
- Tool Registry 只在执行详情接口中做能力展示，未参与业务执行链路；权限控制在各业务 Service 层。
- `task_create` 已开启原生 Tool Calling（`FLA_AGENT_TOOL_CALLING_ENABLED=true`），预览→确认→Service 写入；关闭该变量即回到原正则链路。
- LLM 超时、429、5xx 有统一错误映射；Prompt 文件参与版本和哈希记录。

## 13. 已知风险与技术债

### 13.1 高优先级

1. **Agent 大 JSON 数据仍存在风险**  
   当前 `agent_runs.pending_action_json` 最大约 319,213 字符，`agent_run_events.payload_json` 最大约 319,481 字符，`waiting_confirmation` 仍有 2 条。排序问题已修复，但大字段存储、传输和清理策略仍需治理。

2. **超大任务详情加载仍较重**  
   7,956 词任务详情约 1.5 MB，打开详情仍可能需要数秒。提交答案已经优化为增量处理，但超长任务的详情展示后续应考虑分页或分段加载。

3. **生产构建不可在服务器完成**  
   服务器没有 Node/npm/uv 和 GitHub 网络。发布依赖本地构建，必须严格维护版本和产物 hash。

### 13.2 中优先级

1. Agent 当前单 worker、进程内后台执行，多实例扩容前需共享队列和 Worker 方案。
2. Docker Compose 未在 Docker daemon 环境完整验证。
3. 未接入生产 LangSmith 外部追踪。
4. `/health/metrics` 当前公网可直接访问，建议评估是否加访问限制。
5. 49 张 `legacy_*` 表仍保留，清理前必须确认归档策略和备份。
6. 备份文件需要补充加密、异地保留和定期恢复演练机制。
7. `project2` 运行账号无 sudo，生产切换依赖额外运维账号，需明确责任人。
