# 家庭学习助手部署说明

**版本：** 1.0  
**更新时间：** 2026-11-02

---

## 1. 运行组件

- Backend：Python 3.12、FastAPI、LangGraph、SQLAlchemy、Alembic。
- Frontend：React 19、TypeScript、Vite；生产使用轻量 SPA static server，Nginx 反向代理 `/api`。
- Business DB：MySQL 8.0.19+（本次实际验证 8.4.7）。
- Checkpoint DB：MySQL，使用 `langgraph-checkpoint-mysql`；开发环境可用 SQLite。受限生产主机可与业务库共用同一 MySQL 实例/数据库。
- 文件存储：本地持久卷 `FLA_UPLOAD_DIR`。

## 2. 本地开发

```bash
cd backend
cp .env.example .env
uv sync --dev
uv run alembic upgrade head
uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

```bash
cd frontend
npm install
npm run dev -- --host 127.0.0.1 --port 5173
```

## 3. 必需配置

| 环境变量 | 说明 |
| --- | --- |
| `FLA_ENVIRONMENT` | `development` / `test` / `production` |
| `FLA_DATABASE_URL` | 业务库，例如 `mysql+pymysql://...` |
| `FLA_JWT_SECRET` | 生产必须替换为至少 32 字节随机值 |
| `FLA_SEED_DEMO_DATA` | 生产必须为 `false` |
| `FLA_CHECKPOINT_BACKEND` | 生产为 `mysql` |
| `FLA_CHECKPOINT_URL` | `mysql://user:password@host:3306/familylearning_checkpoints?charset=utf8mb4` |
| `FLA_BOOTSTRAP_ADMIN_1_NICKNAME/PASSWORD` | 首个生产管理员 |
| `FLA_BOOTSTRAP_ADMIN_2_NICKNAME/PASSWORD` | 第二个生产管理员 |
| `FLA_CORS_ORIGINS` | 前端来源 JSON 数组 |
| `FLA_LLM_PROVIDER` | 当前统一为 `openai_compatible` |
| `FLA_LLM_BASE_URL` | `https://api.deepseek.com/v1` |
| `FLA_LLM_MODEL` | `deepseek-v4-flash` |
| `FLA_AGENT_TOOL_CALLING_ENABLED` | 任务创建是否走原生 Tool Calling；默认 `false`，灰度验证后开启 |
| `FLA_LLM_TRACE_ENABLED` | 是否把 LLM 请求/响应写入 JSONL；默认 `false`，仅测试/排障使用 |
| `FLA_LLM_TRACE_PATH` | LLM 追踪文件路径，默认 `./data/llm-trace.jsonl` |
| `DEEPSEEK_API_KEY` | Compose 使用；真实值只写入本地 `.env` |

Bootstrap 管理员仅在昵称不存在时创建，不会覆盖已有密码。生产启动后应从密钥管理系统注入密码，不把 `.env` 提交到 Git。

## 4. MySQL 建库要求

```sql
CREATE DATABASE familylearning
  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE DATABASE familylearning_checkpoints
  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

`langgraph-checkpoint-mysql 3.0.0` 的 `JSON_TABLE` 查询会使用 MySQL 8 默认 `utf8mb4_0900_*` 排序规则。若数据库使用 `utf8mb4_unicode_ci`，Checkpoint 查询可能报排序规则混用错误。

## 5. 生产直接启动

```bash
cd backend
uv sync --frozen --no-dev
uv run alembic upgrade head
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1
```

建议当前版本每个 Agent 执行进程使用单 worker。Agent 图执行在进程内后台线程运行，事件通过数据库持久化；多实例部署时需结合共享 MySQL、反向代理会话粘性和运行租约监控。

前端构建：

```bash
cd frontend
VITE_API_BASE_URL=/api/v1 npm run build
```

将 `dist/` 交给 Nginx，并将 `/api/` 代理到后端。仓库中的 `frontend/nginx.conf` 已包含 SSE 所需关闭缓冲和 300 秒读取超时配置。

## 6. Docker Compose

```bash
cp .env.example .env
# 编辑 .env，替换全部密码和 JWT Secret
docker compose up -d --build
```

访问 `http://localhost:8080`。Compose 包含 MySQL、后端、前端、MySQL 健康检查、上传卷和 Checkpoint 独立数据库。

**验证说明：** 当前交付机器没有可用的 Docker daemon，因此未执行 `docker compose build/up`；已实际验证的是 MySQL 8.4.7 + 直接启动的生产配置、迁移、双管理员 Bootstrap、健康检查和登录。首次在有 Docker 的机器部署时仍应执行一次完整 Compose 冒烟测试。

## 7. 健康检查与监控

- `GET /api/v1/health/live`：进程存活。
- `GET /api/v1/health/ready`：进程与数据库可用。
- `GET /api/v1/health/metrics`：请求总数、错误数、进行中请求、状态码分类和延迟。
- 每个响应包含 `X-Request-ID`；日志包含 method/path/status/duration/request_id。

建议告警：

1. `/health/ready` 连续 3 次失败。
2. 5xx 比例 5 分钟内超过 2%。
3. Agent 失败事件或 `status=failed` 增长。
4. Checkpoint 数据库写入错误。
5. 磁盘剩余空间低于 20%。

LangSmith 可通过标准 `LANGSMITH_*` 环境变量接入；本项目未提供生产 API Key，因此本次没有执行外部 LangSmith 追踪验证，核心业务流程不依赖 LangSmith。

## 8. 备份

```bash
cd backend
MYSQL_HOST=127.0.0.1 MYSQL_PORT=3306 \
MYSQL_USER=fla MYSQL_PASSWORD='***' \
BUSINESS_DB=familylearning CHECKPOINT_DB=familylearning_checkpoints \
BACKUP_DIR=/secure/backups \
./scripts/backup_mysql.sh
```

恢复：

```bash
BUSINESS_BACKUP=/secure/backups/business-XXX.sql \
CHECKPOINT_BACKUP=/secure/backups/checkpoints-XXX.sql \
MYSQL_USER=fla MYSQL_PASSWORD='***' \
./scripts/restore_mysql.sh
```

本次实际演练结果：业务库源/恢复行数均为 `users=4, tasks=1, vocabularies=1`；Checkpoint 源/恢复行数均为 `checkpoints=123, checkpoint_writes=1068`。

## 9. 历史清理

```bash
# 先 dry-run
uv run python scripts/cleanup_agent_history.py --days 30
# 确认后执行
uv run python scripts/cleanup_agent_history.py --days 30 --apply
```

脚本只删除已过期且处于终态的 Agent Run/事件；仅当 Conversation 没有近期 Run 时才删除对应 Checkpoint thread。Conversation 消息不会被清理。

## 10. 发布与回滚

发布：

1. 备份业务库和 Checkpoint 库。
2. 执行 `alembic upgrade head`。
3. 启动新后端并等待 `/health/ready`。
4. 构建/切换前端。
5. 运行核心 E2E。

回滚：

1. 停止新版本写入。
2. 切回上一版本应用镜像。
3. 如迁移不向后兼容，恢复备份后再启动旧版本。
4. 检查 Agent 是否有 `running` 运行；必要时清理租约或等待过期。

## 11. 已知部署限制

- 本次未构建 Docker 镜像；原因见第 6 节。
- 前端 Token 存储于浏览器本地存储，已通过 React 默认转义、内容安全实践和安全响应头降低风险；若需要更强隔离，可后续改为 HttpOnly Cookie。
- 浏览器语音合成依赖操作系统语音包，服务端只下发听写配置。
